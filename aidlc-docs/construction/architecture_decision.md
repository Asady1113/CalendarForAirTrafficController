# 開発方針：モジュラーモノリスアーキテクチャの採用

## 決定事項

**全てSwiftで実装するモジュラーモノリスアーキテクチャを採用する**

## 採用理由

1. **審査コスト**: 変更頻度は月1回未満（バグ修正程度）のため、API分離のメリットは限定的
2. **他プラットフォーム**: Android/Web版は「もしかしたら」程度で不確定。YAGNI原則に基づき現時点では不要
3. **運用コスト**: API分離だとサーバー代・監視が必要。モノリスなら運用コストほぼゼロ
4. **ツーウェイドア**: モジュール設計により、将来のAPI分離は可能（1-2日程度の作業量）

## 実装時の注意事項

### 1. Domain層の独立性を保つ
- UIフレームワーク（SwiftUI、UIKit）に依存しない
- 永続化技術（SwiftData、CoreData）に依存しない
- `@Published`, `@State`などはPresentation層のみで使用
- Swift固有機能を最小限に（将来の他言語移植を考慮）

### 2. Repository パターンで永続化を抽象化
- Domain層にはインターフェース（protocol）のみ定義
- Infrastructure層で具体的な実装
- 将来API化する際は、同じインターフェースでAPI実装に差し替え可能

### 3. テストを充実させる
- Domain層のテストカバレッジ80%以上を目標
- 将来の他言語移植時の正解データとして機能させる

## 将来のAPI化について

以下の条件で必要になった場合に検討：
- Android版の具体的なニーズが確定
- 審査頻度が多く、コストが高い

その際も、Domain層のロジックを他言語（TypeScript/Python等）に移植するだけで対応可能（作業量: 1-2日）
